1

The two systems

Titan ("Chroma") is a multi-product platform — Snack, Book, FactoryAtlas, FleetMap, IP Navigator, IdentityBridge, Orchestration, Pipeline — over a shared fleet of 32 runtimes in 11 capability groups. Its doctrine inverts the usual question: not who is this user? but what is allowed right now? — collapse resistance, scoped authority, boundary-native architecture, temporal containment. Composition: Product → Runtime → Contract → Broker → Provider → Receipt, with "credential boundary = product boundary" and contracts as "the only allowed language between systems."

Infinite-Verse is a semantic cultural knowledge and experience platform: it "admits authorized physical and digital sources, resolves durable publication and corpus identity, records meaning with provenance and confidence, and powers integrated products through governed projections." Manga Verse is the first domain. It pins the same protocol suite this project pins, plus iPub — its immutable publication format over content-addressed bytes, with semantic envelopes attached by reference. It is, in effect, a sibling attempt at this project's thesis: an unusually well-specified contract corpus with a partial implementation.

Net relationship: Infinite-Verse confirms the design's spine and runs ahead of it on qualification and projection governance; Titan supplies the operational machinery — custody, realtime transport, observation, constitutional CI — that the design describes but does not yet specify. The Field plane is the one place the CMS design leads both.

2

Verdict summary

The six-plane architecture survives contact

Both systems independently converged on the same separations: append-only truth, governed writes, evidence-gated promotion, regenerable projections, disclosed observation. Nothing found contradicts the design's spine.

Two planes are missing

Infinite-Verse demonstrates that Admission (what may enter, under what rights) and Entitlement (who may see what, at section granularity) are distinct planes — a CMS that skips them grows them accidentally, per-projection.

Qualification needs a fourth verdict column

Both systems learned the same lesson: "could not run" and "never ran" must block promotion exactly like "failed" — and gates must be provably able to fail (vacuous-pass detection, evaluator self-tests).

Live co-authoring has a second lawful answer

Titan's Generative Relationship Protocol shows divergence-first collaboration — permanent legal branches over an immutable DAG, merge as an explicit authored act — which composes with append-only Canon better than silent convergence.

Live propagation has a proven transport

Transactional outbox → LISTEN/NOTIFY fanout → backfill-then-live → last_event_id replay → lagged disclosure. No new infrastructure, no event loss, staleness disclosed as protocol messages.

Live honesty is richer than the design knows

Two-clock freshness with tracked skew, hysteresis on state transitions, presence announced not inferred, UNKNOWN rendered as its own state, and absence carrying a reason code.

Plane-by-plane findings

Cconfirms the design Bbetter mechanism than the design specifies Nnovel, applicable Ggenerative, not directly applicable

NPlane 0 — Admission (missing from the design)

Infinite-Verse records, for every source intake: custody, a set of permitted operations (inspect · normalize · ingest · enrich · train · redistribute — "a physical purchase does not automatically authorize digitization, model training, or redistribution"), rights scope, retention, and identity disposition. Four outcomes, including metadata-only — a source that participates in discovery with zero byte-processing authority. The ingestion rule: "a file becomes a publication in one transaction; it becomes comprehended afterwards, asynchronously, and never blocks becoming readable."

CBCanon

Confirmed: append-only enforced in the store (triggers, grant-less roles, "no UPDATE or DELETE paths"); JCS→SHA-256 content identity; supersession lineage; hash-linked receipts.

  • Teaching triggers — the append-only trigger's exception message states the correct procedure ("re-project into a new revision under a newer ruleset_version"). Enforcement that educates.
  • Identity is minted, never derived. A per-job mint ledger makes retried commits idempotent while new jobs mint fresh identity for identical bytes; an identity_scheme column with no DEFAULT ("a default would silently label a row nobody classified"). Its inverse discipline in GRP: hash-input selection as a design act — IDs exclude timestamps and model output so retries converge. Shared rule: nothing derived from a detector or model output is identity-stable across versions.
  • Idempotency conflict detection — same key + same payload → dedup; same key + different payload → 422. "Prevents silent corruption."
  • Transactional outbox — the domain write and its event row commit in one transaction; audit INSERT shares the transaction with the state UPDATE, so an optimistic-lock failure rolls back both.
  • Vocabulary version witnesses on every row (ruleset_version, parser_or_model_version…) — "which rows predate the fix?" becomes a query, not archaeology.
  • Migrations as design records — 312-line migrations that are ~70% argument, including "What this migration deliberately does NOT do."

CBContracts

Confirmed: single write door; typed outcomes; executable recovery; optimistic concurrency where the 409 carries what you need to converge (expected_base_digest; the legal next-state list).

  • The fourth custody clause: every component declares owns / may consume / may issue / must never become, with forbidden_reads/forbidden_writes — and the declarations are derived from the actual route surface by tooling, flagged for human confirmation. The named failure set: "coordinator → hidden user graph, broker → credential sink, runtime → tenant state holder, provider → identity authority, client → trusted state source."
  • Constitutional CI: doctrine compiled into greps — "must not persist memory" enforced by grepping for ORM imports; illegal-states tables (illegal state → prevention mechanism → status → evidence).
  • "Absent ≠ false" as a written consumer rule: additive-only contract versioning where absent fields mean not declared, never a positive assertion — plus an explicit connections_declared "I haven't told you" flag.
  • PATCH tri-state: absent key ≠ explicit null ≠ {} — assembled key-by-key because a spread collapses them.
  • Client pre-flight three-law: never looser than the server, never masks a server decision, counts code points — stricter-only is the one direction contracts may deviate.

CBNQualification

Confirmed: qualification ≠ promotion — Infinite-Verse attestations carry qualificationAuthority: "qualify-deployment.py" with promotionAuthority: null, structurally separated, with mandatory limitations[].

Promotion over partial coverage asserts more than was established. Full coverage or no promotion — "could not run" and "never ran" block exactly like "failed."

Infinite-Verse promote-staging.py · the four-column verdict
  • The vacuous-pass gate: run every evaluator against a populated corpus and an empty one; a gate that can observe absence must not return green on the empty one. Behavioral, not syntactic. Measured impact: 22 phantom passes before it existed. Half the gate roster ships a self-test twin proving it can fail.
  • Delivery-time qualification (Titan Book): every citation in a generated response must resolve into the exact evidence set retrieved for this request; one unresolvable citation blocks the whole artifact — never partial. The adversarial challenger is non-blocking. And the decision is fingerprinted, not just the artifact — over (namespace, policy_version, outcome, attempts, verified_ids) — so a block is as auditable as a publish, and a policy change provably changes the fingerprint.
  • Two-tier materiality: machine attachments are non-material (re-detection mints no revision); human-verified work may be promoted to material, which mints a revision — "making editorial work part of publication identity."
  • Freshness as an obligation field: each obligation names its own invalidation event ("a redeploy invalidates it"). And qualify what is served, not what is configured — "config is not the artifact."
  • Content-safe promotion: "Ancestry lies" — compare content trees, not commit graphs. A promotion-lock race exits could-not-verify, never refused.
  • Prose gates: claim-reconciliation tables (✅/⚠️/❌/❓ per public claim, "anything not ✅ should not appear in copy") and the operational promise register — promises with no code identifier extracted into a machine-checked register, because "verifiable claims fail loudly; promises fail silently."
  • Fabrication lint: "absent stays absent" — no invented defaults; a guess must be declared as a diagnostic. "This gate is the memory" of five hand-removed fabrications.

CBProjection

Confirmed: stored-vs-derived doctrine stated identically in both systems — "Measured, with provenance and confidence" vs "Regenerable. Never written back into the publication." Six-dimension projection profiles running in production registries. "The UI never reads tables. It requests a view."

  • computed_from lineage: every projection row carries the digest-set it was computed from; stale is a join against append-only invalidation records; never-computed ≠ stale; stale-while-revalidate only if the marker stays visible. Composes with the design's fingerprint invalidation: fingerprints propagate invalidity, computed_from makes staleness queryable.
  • Declared refresh policy per projection — eager (writer pays) / lazy-on-read (first reader pays) / scheduled (batch pays), lazy by default — and human-verification eagerness overrides every policy: "a human corrects a speaker attribution and the search document still serving the machine's guess an hour later squanders exactly the authority the two-tier model exists to protect."
  • Supersession declared, never inferred — same scope, same detector class, explicit lineage; "timestamps must not be used to guess an ordering"; human documents never superseded by machine re-runs. Multiplicity is the default — disagreement stays visible.
  • One merge function for reader and owner, with access as a parameter — "so a reader and an owner can never see two different merges of the same documents."
  • Derivative classes, not encodings — manifests declare thumbnail / preview / reader-medium / reader-large; codecs live downstream so re-encoding can't change content identity.

CNField — the design leads; two additions

Both systems know what to measure (eight normalized page dimensions; a typed signals taxonomy) but neither has a live field — the design's Fundamental-based plane leads. Two additions:

  • The Library Substrate canvas is the Field plane's missing evidence layer, already working: 10 z-normalized dimensions, k-means shelves with cohesion, an evidence floor as a live, unit-labeled control, and name qualification — a curated shelf name applies only when its signature matches and cohesion clears 0.55; otherwise the refusal is rendered with the actual and required numbers and the cluster keeps its machine description ("negative space +1.42σ · dialogue density −0.88σ"). A standing expectation harness — "N of 12 assertions hold" — runs tests of meaning over live data. Observations are revision-scoped with named confounds: the same work measures differently per edition; "ink coverage must be normalised per revision before clustering."
  • Signals governance (Titan): server-truth vs client-reported (advisory only) vs derived metrics with mandatory TTLs ("permanent behavioral histories are forbidden") — and a deliberately lossy boundary: only a coarse verdict crosses out of the Field, never a rich profile; the Field "does not know handles exist." Plus per-field truth types (semantic / canonical / operational / abstain) driving both retrieval and re-derivation policy.

CBNObservation

  • Presence and transport are two axes — HOT/ACTIVE/IDLE/STALE/OFFLINE/UNKNOWN × HEALTHY/DEGRADED/UNHEALTHY/OFFLINE/UNKNOWN — with UNKNOWN rendered, not blank: "we don't know" ≠ "not here."
  • Two-clock freshness: staleness computed against server-issued time with tracked skew — "every 'updated 3s ago' badge you'd otherwise ship is a lie on a skewed client."
  • Presence is announced, not inferred: a runtime that starts healthy and never transitions is invisible — "'missing' and 'healthy' look identical" (measured: 23 configured, 1 event seen). Heartbeats fire on edges with auto-composed numeric reasons; Degraded is a serving state distinct from Down.
  • Disclosed subscriber staleness: the event stream emits lagged when a subscriber falls behind — staleness as a protocol message, with catch-up-then-live as the canonical consumer shape.
  • Absence with a reason code: every scalar is {value, source, confidence, absent_reason} (NO_STORE / NO_WRITER / NOT_CAPTURED); off-ladder observations render (off-ladder) and sort last, visibly. Three absence granularities — empty / absent / error — never merged; named-absence routes stay deep-linkable with declared: false distinguishable from designed absence.

NEntitlement — underspecified in the design

Infinite-Verse treats entitlement as its own model, twice: section-level access classes — every semantic section is open (geometry, metrics, relation topology: "what shelves and similarity run on") or entitled (all text layers, anything "precise enough to reconstruct narrative"), enforced by one shared restriction function "so this route cannot become a second, laxer definition of what open means" — and the five-record independence rule: ProviderAssertion ≠ ProviderTransaction ≠ EntitlementClaim ≠ EntitlementProjection ≠ LibraryEntry, evidence flowing one way, claims never destructively merged, projections recomputable-from-claims with a fixture-replay gate. Plus 404-not-403: absence copy must not confirm existence to someone probing.

4

The realtime obligations, revisited

R1 — live co-authoring

  • The divergence-first lane. Neither system uses CRDTs anywhere. GRP's answer — immutable typed nodes, 23 edge types, paths as projections over the DAG, sibling branches structurally invisible to each other, and merge as an explicit authored act in five modes (synthesize / replace / augment / overlay / compare_then_merge, with overlay "preserving each voice") — composes with append-only Canon in a way silent convergence cannot. Its traversable-relationship whitelist (only 6 of 23 edge types carry context; contradicts is recorded but does not propagate) separates edge semantics from edge reachability. Proposal: CRDT stays for micro-convergence inside a draft's free fields; branch/authored-merge handles document-scale divergence.
  • changeCertainty. Every write outcome carries asserted / derived / indeterminate alongside changed — and indeterminate must carry a retry bound to the original idempotency key. The difference between "your edit didn't save" and "we don't know whether it saved" — only the second has a safe remedy. Companion: receiptSurrogate — receipt-shaped responses that are not receipts travel under a different name, because "a client that constructs one has produced an audit record for an event it did not witness."
  • Rendered-set-bounded deletion. Deletes are authorized only for records the actor was actually shown; omitting the set means "shown nothing," so nothing may be deleted. Shipped-bug provenance: a diff against a fetched-but-unshown envelope turned one mark into 1 add + 20 deletes, reported as success. And on a stale reorder: deliberately no "try again" — re-sending would discard the other writer's work.

R2 — live propagation

Nothing happens without an emission. The audit log, the dashboard, the dead-letter queue, the SLA monitor, and downstream replicas are all subscribers to the same stream the system needed to emit for its own integrity.

Titan Pipeline — the transport doctrine

The proven shape: transactional outbox as the sole emission source → LISTEN/NOTIFY fanout (horizontal-safe, no new infrastructure) → scoped subscriptions → backfill-burst-then-live on connect → reconnect with last_event_id replayed from the outbox ("no event loss" as an acceptance criterion) → lagged overflow disclosure. The client seam is a Stream<T> contract that mocks drive with scripted frames, "so realtime code paths run for real long before a socket gateway exists."

R3 — live honesty

Two-clock freshness; hysteresis with instrumentation; announce-on-start; UNKNOWN rendered; mockIsSilent as a defect class — mock data present without a URL-discoverable override ("a screenshot of mock content was verified as 'live mode'"); staleness disclosures on frozen exports; and the compiled-corpus header that names its own payload hash, dirty flags, and STALE INPUT banner — the pattern for this project's own compiled context.

5

Cross-cutting governance

  • Gates provably able to fail, operationalized: vacuous-pass detection, self-test twins, gate-enumeration and invocation-coverage gates, and provenance stamps on every run — "a bare '29/29 full coverage' cannot be verified by anyone, including its author a day later."
  • Deviation register with escalation: violations are permitted if filed — blast radius, rotation, reversal trigger, owner — and an unfiled violation auto-escalates one severity level.
  • Assurance never aggregated: ten independent dimensions, generated from the registry so the table can't drift, with deliberately no score — "a percentage is how a table like this starts lying."
  • The spec-health register: a tagged list (GUESS / GAP / THIN / CAVEAT) of exactly where a spec forces a builder to invent — "listed so the invention becomes a decision instead."
  • Doc-vs-code drift typed: VIOLATION (code wrong) vs INACCURACY (docs wrong), with Built/Partial/Paper self-labels.
  • A naming collision to resolve deliberately: Titan's "planes" (Record/Event/Workflow/Policy/Retrieval) overlap but differ from this design's six — a bindings entry should align or explicitly diverge; silence would be drift.

Independent adversarial pass · 2026-08-28

Both systems' own accounting bounds every claim above. Titan: the planes directory doesn't exist; 1 of 32 runtimes carries its mandatory authority doc; the SEC-* policy suite is referenced everywhere and exists nowhere; one safety gate "fails open." What survives its own reality check — and is safest to copy — is the code-backed set: fleet-contract/tracker, grounding-gate, canonical-serializer, event-runtime, the boundary checker, manifest generation. Infinite-Verse: its 26-gap implementation register is scrupulous — no work table, manifests not served, the manifest hash not yet a hash; "members of twenty-two implemented conformantly end-to-end: still none." Borrow on the strength of the reasoning, not on scale evidence. This review is a single pass, observed, not adversarially verified.
