# Mental Model

These concepts are easiest to understand progressively.

## Level 1 — Four questions

1. **What is true?** → Canon
2. **What matters here?** → Surface
3. **How should it appear?** → Expression
4. **What is allowed to happen?** → Interaction

This is the primary learning model.

```text
Truth → Relevance → Expression → Action
```

## Level 2 — Familiar contrast

A conventional CMS says:

```text
Here is a page.
Edit the page.
Publish the page.
```

A Semantic CMS says:

```text
Here is the meaning.
Resolve what matters for this context.
Express it appropriately.
Govern any consequential change.
```

## Level 3 — One example

For an article:

- Canon: the article, author, evidence, relations, revision, and publication state.
- Surface: what matters to the current reader, editor, reviewer, or operator.
- Expression: how that semantic surface is presented.
- Interaction: what operations may cross into consequential change.

## Plain-language vocabulary

| Formal term | Plain language |
|---|---|
| Canon | what the system says is true |
| Surface | what matters here |
| Expression | how it appears |
| Representation | what someone actually encounters |
| Provenance | where this came from |
| Qualification | whether there is enough evidence |
| Promotion | making the consequence real |
| Consistency | how current this view is |
| Withheld | something may exist, but access does not permit participation |
| Resolution trace | why this is here |

## Progressive disclosure

Most users should not need protocol vocabulary. Product copy should explain meaning rather than implementation.

Examples:

- `ResolvedSurface` → “Why you’re seeing this”
- `stale-but-safe` → “This view is 1 revision behind”
- `withheld` → “Available with additional access”
- `qualification inconclusive` → “Not enough evidence yet”

The formal terms remain available for technical inspection, auditing, conformance, and development.
