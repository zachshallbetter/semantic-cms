# Interaction Principles

## Simple interaction, inspectable truth

Complexity should live in the system, not in constant user ceremony. Ordinary work should remain direct, while deeper state, provenance, and evidence are available when needed.

## Content first

The semantic object should dominate the interaction. Administrative chrome should not become the primary mental model.

## Navigate by intent and meaning

Users should increasingly be able to navigate through questions such as:

- what needs attention?
- what relates to this?
- what changed?
- what supports this?
- what contradicts this?
- what is ready?
- what is uncertain?
- what happened?
- what can I do about it?

## The same subject, different purpose

Moving between Edit, Understand, Qualify, Monitor, Compare, Trace, and similar purposes should change the surface around the subject without implying that the subject itself changed.

## Explain dynamic behavior

If the application reorganizes itself contextually, the user must always have a dependable way to inspect why an item appeared, disappeared, moved, or changed role.

## Conflict freezes consequence, not drafting

Users should continue ordinary drafting where safe. Consequential operations should stop when required meaning is conflicted.

## Do not imply more freshness than exists

A surface should show whether it is live, stale, snapshot-based, local, conflicted, or unknown rather than using generic “online” indicators.

## Absence has meaning

Do not flatten unknown, withheld, absent, unavailable, unsupported, or hidden into one empty state.

## Relationships do not automatically cause behavior

A relation may inform a surface but does not automatically create recommendation, ranking, promotion, or action.

## Humans and agents use the same semantic substrate

A human interface and a machine-facing interface may be radically different expressions of the same resolved semantic participation.
