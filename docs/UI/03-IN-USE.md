# What It Looks Like in Use

The application behaves less like a fixed set of CMS modules and more like a workspace that resolves the semantic state relevant to what the user is doing.

## Operate

A user may begin with a purpose such as `operate`. The system resolves active work, unresolved conditions, ready candidates, delivery issues, and recent change. This is not necessarily a fixed dashboard; it is a surface produced from current state.

## Focus

Selecting an object changes the semantic center. The system can then resolve that subject for a specific purpose.

For `edit`, the surface may emphasize editable structure, supporting assets, unresolved obligations, relationships, and available operations.

For `understand`, the same subject may emphasize evidence, contradictions, people, concepts, and history.

For `monitor`, it may emphasize delivery state, propagation, freshness, and drift.

## Traverse relationships

Users can move through meaning rather than only through route hierarchies:

```text
Article
   ↓
Researcher
   ↓
Study
   ↓
Concept
   ↓
Collection
```

## Search as resolution

Search can become a request for a semantic surface rather than a list of matching rows.

Examples:

- everything related to a subject that changed this month and has unresolved evidence;
- published material affected by a revised source;
- records that reference superseded evidence;
- work needing attention under the current user’s authority.

## Compare

Comparison is not limited to side-by-side fields. A comparison surface may identify shared concepts, distinct claims, disagreement, missing evidence, and unknown relationships while retaining the basis for each distinction.

## Time travel

A temporal surface can reconstruct what the system knew, what was promoted, and what was observed at a prior point in time. History becomes semantic reconstruction rather than merely an undo list.

## AI participation

An agent can receive the same resolved semantic participation as a human, expressed in machine-readable form. It reasons over bounded, provenance-bearing context and produces candidates rather than silently mutating canonical state.

## Typical flow

```text
OPERATE
What needs me?
     ↓
FOCUS
Why does this need attention?
     ↓
UNDERSTAND
What is connected to this?
     ↓
COMPARE
How do these sources differ?
     ↓
EDIT
Revise the affected material.
     ↓
QUALIFY
Is this supportable?
     ↓
PROMOTE
Make this revision consequential.
     ↓
MONITOR
Did it actually propagate?
     ↓
TRACE
What happened and why?
```

These purposes do not have to map one-to-one to application modules. They are different ways of resolving the same semantic system.
